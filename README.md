## Deploying the Next.js app
`npm run build` writes a complete static site to `out/`: one HTML file per page (`out/cness-advantage.html`, `out/mother-of-certification.html`, ...), the `_next/` folder (fingerprinted scripts, styles and fonts), `assets/`, `favicon.ico`, `icon.png`, `robots.txt`, `404.html` and `_headers`. No server code runs; any static host or CDN can serve it.
- **Host settings.** Serve `/<page>` from `<page>.html`, and `/<page>/` either the same way or with a redirect to `/<page>` (the live site answers both forms). Serve `404.html` with status 404 for unknown paths. Compress text files (gzip or Brotli). Cache `/_next/static/*` for a year (`immutable`); revalidate pages. Cloudflare Pages and Netlify do the path mapping on their own and read `out/_headers` (security headers, caching, `X-Robots-Tag: noindex`). For nginx:
  ```
  location / { try_files $uri $uri.html $uri/ =404; }
  location ~ ^/(.+)/$ { return 308 /$1$is_args$args; }
  location /_next/static/ { add_header Cache-Control "public, max-age=31536000, immutable"; }
  error_page 404 /404.html;
  gzip on; gzip_types text/css application/javascript text/plain image/svg+xml;
  ```
  `npm run serve` behaves this way (both URL forms, compression, caching, 404 page), so the tests run against what a host would serve.
- **Under a sub-path.** For a preview at e.g. `https://staging.example.com/preview/`, build with `NEXT_PUBLIC_BASE_PATH=/preview npm run build` (serve with the same variable). Links, images, fonts and page switching follow the base path; `node tools/test-deploy.js http://localhost:3100/preview` and the verifiers pass in this mode.
- **Links between the old and new site.** Links to pages this app serves are local; links to pages it does not serve yet (home, Global Directory, Best Practices, About, sign-up and log-in) go to `https://www.cnessworks.com/...`. If the app is deployed on www.cnessworks.com for only some paths, route those five paths (plus `/_next/`, `/assets/`, `/favicon.ico`, `/icon.png`) to it.
- **Security headers.** `out/_headers` sets `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`, `Permissions-Policy` and HSTS. A Content-Security-Policy is not set: Next.js puts small inline scripts in every page (page data, and each page's first-paint script), so a CSP would need `'unsafe-inline'` for scripts or per-build hashes; add it at the host if the site's policy requires one.
- **Metadata.** Each page has its own title, description, canonical production URL (`https://www.cnessworks.com/<page>`) and sharing card (Open Graph), and the CNESSWORKS tab icon from the live site.
- **Going live (search engines).** The site is kept out of search engines in three places; remove them at go-live, and only then: `robots: { index: false, follow: false }` in `lib/site.ts` (`pageMetadata`, used by every page) and in `app/layout.tsx`, the `X-Robots-Tag` line in `public/_headers`, and the rules in `robots.txt` (`scripts/sync-assets.mjs` copies it into the build).

## First Light (`immersive.html`)
A cinematic, condensed version of the same content. Copy is shortened but every statement comes from CONTENT.md.
- One fixed WebGL field of particles (36,000 on desktop, 14,000 on phones) sits behind the whole page. Each particle has eight stored positions, one per formation: nebula, six-facet lens, wave, five-node helix, three rings, heptagon, globe, sun. The vertex shader blends between them from a single `uScene` value, so a chapter change is a morph, not a cut.
- Chapters are `.ch[data-scene]` sections. Each pins for `--len` viewports; `layout()` in the main script turns scroll position into the scene value (held while pinned, blended over the last viewport before the next chapter), the per-chapter `--p` progress, and the active step. Steps (`[data-step]`) light the matching facet, node, ring or vertex through `CW.hi`.
- Other scroll-driven pieces: the horizontal "Four ways" track, rising headline lines, the word-by-word statement, the sky colour, and the final sunrise (a `clip-path` circle that takes the page from night to day).
- Formations, colours, placement and spin are plain data at the top of the main script (`CW.forms`, `CW.colA/colB`, `CW.rig`, `CW.spin`). The Canvas 2D fallback (`draw2d`) draws the same data when WebGL or the CDN is unavailable.
- Pause motion and `prefers-reduced-motion` stop time-based motion and make scene changes snap; scrolling still moves between chapters. It keeps the `noindex` tag.

## Standalone HTML files (`dist/`)
Single-file versions of the pages, ready to hand over or open directly in a browser:
- `dist/cnessworks-first-light.html`: First Light.
- `dist/cnessworks-advantage.html`: the CNESS Advantage subpage.
- `dist/cnessworks-certification.html`: the Certification section (three pages).
- `dist/cnessworks-analyze.html`: the Analyze page (Organization and Product paths).

Each file is a complete HTML document with every image (logo, level emblems, CNESS mark) embedded as a data URI, so it needs no `assets/` folder. Two things still load from the internet: the Google Fonts stylesheet, and three.js from jsDelivr for the WebGL particles (not used by the Certification file, which has no WebGL). Without three.js the pages fall back to the Canvas 2D drawing; without the fonts they use the fallback faces.

To regenerate after editing any source, run `./build.sh`, then:
```
python3 - <<'EOF'
import base64, re
for src, out in [('immersive.html', 'dist/cnessworks-first-light.html'), ('advantage.html', 'dist/cnessworks-advantage.html'), ('certification.html', 'dist/cnessworks-certification.html'), ('analyze.html', 'dist/cnessworks-analyze.html')]:
    s = open(src, encoding='utf-8').read()
    for a in sorted(set(re.findall(r'assets/[\w./-]+\.(?:png|svg|webp|jpg)', s))):
        mime = {'svg': 'image/svg+xml', 'png': 'image/png', 'webp': 'image/webp', 'jpg': 'image/jpeg'}[a.rsplit('.', 1)[1]]
        s = s.replace(a, f"data:{mime};base64," + base64.b64encode(open(a, 'rb').read()).decode())
    open(out, 'w', encoding='utf-8').write(s)
EOF
```
